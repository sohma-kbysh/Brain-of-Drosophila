# 有効なGPT-like挙動とresource estimation：最初の集計

[現行方針](resource_priority.md)に従い、1Dで固定したモデルと保存データから、順序依存と費用に対する予測性能を集計した。新しい神経試行、モデルの再学習、次元・ridgeの再選択は行っていない。これは既存データの探索的な再解析であり、新しい独立確認実験ではない。

## 同じ測定予算での有用性

準備一個あたりの総測定数Bを揃えた。操作的モデルは7個の未来テストに予算をほぼ等分し、即時モデルは一つのテストに全てを使う。元の4座標モデルと即時モデルは固定し、保存outcomeの先頭から状態を推定した。

| 総測定数B | 操作的モデル：確率RMSEの上限 | 即時モデル：同上 | 期待Brier損失の改善区間 | 判定 |
|---:|---:|---:|---|---|
| 200 | 0.12040 | 0.05283 | [-0.013080, -0.008855] | この条件では操作的モデルが劣る |
| 2,000 | 0.04415 | 0.04830 | [-0.000966, 0.001132] | 改善は未確認 |
| 10,000 | **0.02808** | 0.04784 | **[0.000155, 0.001826]** | 同じ測定予算で改善を確認 |

区間は、元の64評価確率を同時95%で覆う二項領域から求めた。改善は「即時モデルの損失−操作的モデルの損失」と定義する。両モデルの全予測は[0,1]内だった。

元の操作的モデルは7万測定でRMSE上限0.01848だった。一方、**測定予算が小さいと4座標モデルの状態取得誤差が大きくなり、利点が失われる**。現時点で得られた資源像は、指定の測定予算で引き出せる予測能力と、そのアクセス費用の関係である。

予算10,000は、調べた有限条件で改善が出た一つの点であり、必要最小予算ではない。予算間は入れ子の試料で、anchorを取り直した際の平均性能や全履歴への保証も得ていない。学習費用・モデル記憶量・更新演算数は二方式で同一ではなく、総費用まで一致させた優位とも区別する。

## GPT-like挙動の一要素：入力順序への依存

28履歴に対して、未来入力 `01` と `10` の終端確率を比較した。同じ入力時間、同じ1の個数で順序を変えている。元の28×15確率表全体を同時95%で覆った上で、4履歴で差の区間が零を除外した。

代表履歴 `00` では、`p(01)-p(10)` の推定値が **-0.0690**、区間は **[-0.09788,-0.03997]** だった。28履歴中の最大絶対順序差の区間は **[0.03997,0.09788]** である。

この観測を、操作の順序に応じて利用可能な応答が変わるという有効挙動として記録する。順序依存そのものの測定と、その順序依存を使った課題での容量測定は別の段階であり、後者はこれから行う。

## 表現・更新の費用見積もり

float64を採用し、固定unit座標を省いたアフィン表現を想定した見積もり。

| 項目 | 4座標モデル | 即時モデル |
|---|---:|---:|
| 状態の数値payload | 32 byte | 8 byte |
| 初期化encoderを含む圧縮したモデルpayload | 640 byte | 64 byte |
| 現在の密行列配列の数値payload | 720 byte | 96 byte |
| 入力1回の更新 | 16乗算＋16加算 | 1乗算＋1加算 |
| 4入力先の予測1個：更新＋読出し | 136演算 | 10演算 |

これらは選んだ数値精度での実装見積もりで、物理系の記憶容量や消費エネルギーではない。Python/JSONの管理領域、学習、状態初期化の演算、測定・再準備、神経シミュレータはこの演算数に含めない。現時点では、アクセス・初期校正の費用を含めた全体の比較が必要である。

## 次の主実験

1Eの主目的を、記憶課題と時間をまたぐXOR等の非線形課題について、能力対測定予算・読出し予算の関係を測ることに置く。観測ノイズや入力揺らぎに対する性能維持も資源指標とする。時間刻みへの感度は、この推定の誤差要因として並行して評価する。

今回の集計は有用性・アクセス費用の最初の測定であり、記憶容量、非線形処理容量、noise toleranceはまだ数値化していない。厳密なGPT公理への適合証明を、それらの測定の前提には置かない。
